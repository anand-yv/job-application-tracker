# Entities

Package: `com.jobtracker.api.model`. Database: PostgreSQL 16.

Schema is generated by Hibernate (`spring.jpa.hibernate.ddl-auto: update`) —
there are no migration scripts. All primary keys are `UUID` with
`@GeneratedValue(strategy = GenerationType.UUID)`. All entities use Lombok
`@Data`, `@NoArgsConstructor`, `@AllArgsConstructor` (see
[KI-08](known-issues.md#ki-08)).

Unless stated otherwise, `String` fields map to `varchar(255)` (Hibernate
default).

## Relationship overview

```
User 1 ──── * JobApplication          (JobApplication.user, unidirectional)
User 1 ──── * Contact                 (Contact.user, unidirectional)
Contact * ── * JobApplication         (join table application_contacts;
                                       Contact is the owning side)
```

## User

Table: `users`

| Field | Java type | Column | Constraints / notes |
|---|---|---|---|
| `id` | `UUID` | `id` | PK, generated |
| `email` | `String` | `email` | `NOT NULL`, `UNIQUE` |
| `passwordHash` | `String` | `password_hash` | Nullable (intended for future OAuth-only users). BCrypt hash |
| `authProvider` | `String` | `auth_provider` | Nullable. Always set to `"LOCAL"` on register. Comment mentions `"GOOGLE"`, which is never used |
| `createdAt` | `LocalDateTime` | `created_at` | Set in `@PrePersist` |
| `updatedAt` | `LocalDateTime` | `updated_at` | Set in `@PrePersist` and `@PreUpdate` |

**Relationships:** none mapped on this side (no collections of applications or contacts).

## JobApplication

Table: `job_applications`

| Field | Java type | Column | Constraints / notes |
|---|---|---|---|
| `id` | `UUID` | `id` | PK, generated |
| `user` | `User` | `user_id` | `@ManyToOne` (default EAGER fetch). FK to `users`. Not declared `nullable = false` |
| `roleTitle` | `String` | `role_title` | `NOT NULL` |
| `company` | `String` | `company` | `NOT NULL` |
| `jobId` | `String` | `job_id` | External job ID |
| `jobUrl` | `String` | `job_url` | varchar(2048). Request `@Size(max = 2048)` |
| `status` | `ApplicationStatus` | `status` | `NOT NULL`, `@Enumerated(EnumType.STRING)` (stored as varchar). Defaults to `APPLIED` in Java |
| `source` | `String` | `source` | Free text (e.g. LinkedIn) |
| `notes` | `String` | `notes` | `text`. Request `@Size(max = 10000)` |
| `salaryRange` | `String` | `salary_range` | Free text |
| `location` | `String` | `location` | |
| `appliedDate` | `LocalDate` | `applied_date` | |
| `contacts` | `Set<Contact>` | — | `@ManyToMany(mappedBy = "jobApplications")` — **inverse side**. Excluded from Lombok `toString`/`equals`/`hashCode` |
| `createdAt` | `LocalDateTime` | `created_at` | `@PrePersist` |
| `updatedAt` | `LocalDateTime` | `updated_at` | `@PrePersist` / `@PreUpdate` |

**Helper methods** (keep both sides in sync):
- `addContact(Contact)` — adds to `contacts` and to `contact.jobApplications`.
- `removeContact(Contact)` — removes from both.

Because this is the inverse side, changing only `jobApplication.contacts`
would not persist; the helpers write the owning side too.

## Contact

Table: `contacts` — `UNIQUE (user_id, email)`

| Field | Java type | Column | Constraints / notes |
|---|---|---|---|
| `id` | `UUID` | `id` | PK, generated |
| `user` | `User` | `user_id` | `@ManyToOne` (default EAGER). FK to `users`. Not declared `nullable = false` |
| `name` | `String` | `name` | `NOT NULL` |
| `email` | `String` | `email` | Nullable. Unique per user (Postgres allows multiple `NULL`s) |
| `phone` | `String` | `phone` | |
| `company` | `String` | `company` | |
| `position` | `String` | `position` | |
| `notes` | `String` | `notes` | `text`. Request `@Size(max = 10000)` |
| `jobApplications` | `Set<JobApplication>` | — | `@ManyToMany` **owning side**, `@JoinTable(name = "application_contacts", joinColumns = contact_id, inverseJoinColumns = application_id)`. Excluded from Lombok `toString`/`equals`/`hashCode` |
| `createdAt` | `LocalDateTime` | `created_at` | `@PrePersist` |
| `updatedAt` | `LocalDateTime` | `updated_at` | `@PrePersist` / `@PreUpdate` |

Deleting a `Contact` automatically removes its `application_contacts` rows
(owning side). Deleting a `JobApplication` requires unlinking first — done
manually in `ApplicationServiceImpl.deleteApplication`.

## application_contacts (join table)

No entity class; defined by the `@JoinTable` on `Contact.jobApplications`.

| Column | References |
|---|---|
| `contact_id` | `contacts.id` |
| `application_id` | `job_applications.id` |

---

## ApplicationStatus (enum)

Not an entity; stored as a string in `job_applications.status`.

`APPLIED`, `SCREENING`, `INTERVIEW`, `OFFER`, `REJECTED`, `WITHDRAWN`

## Repositories

| Repository | Entity | Query methods |
|---|---|---|
| `UserRepository` | `User` | `findByEmail(String)` |
| `ApplicationRepository` | `JobApplication` | `findByIdAndUser(UUID, User)`, `findByUser(User)` *(unused — see [dead-code.md](dead-code.md))*. Also extends `JpaSpecificationExecutor` → `findAll(Specification, Pageable)` |
| `ContactRepository` | `Contact` | `findByUser(User)`, `findByIdAndUser(UUID, User)`, `findByUserAndEmail(User, String)`, `findByUserAndEmailAndIdNot(User, String, UUID)`, `findByIdInAndUser(List<UUID>, User)` |

All are derived queries; there are no `@Query` methods.

**Specifications** (`ApplicationSpecifications`): `hasUser(User)`,
`hasStatus(ApplicationStatus)`. Four more are commented out — see
[dead-code.md](dead-code.md) and [features-todo.md](features-todo.md).
